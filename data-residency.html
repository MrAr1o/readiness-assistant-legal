Data Residency - Readiness Assistant

Document status: Public operational summary

App: Readiness Assistant

Operator: SteikTech, Uilliam Leon Steik

Last updated: July 7, 2026

Version: 1.0

This page explains how data residency works for Readiness Assistant and what customers should verify in Atlassian Administration.

1. Short Answer

Readiness Assistant is built on Atlassian Forge. The app uses:

  • Atlassian Forge functions for app execution;
  • Atlassian Forge Storage for persistent app data;
  • Confluence Cloud APIs for read-only page and space access;
  • optional Atlassian-hosted Forge LLM routing for administrator-triggered AI assistance.

Readiness Assistant does not use a SteikTech-operated app server, external database, external analytics platform, external CDN for customer data, or direct vendor AI API.

Data residency for in-scope app data is governed by Atlassian's Forge and Confluence data residency behavior. SteikTech does not independently choose or override the customer's Atlassian residency location.

2. In-Scope App Data

The following data is treated as in-scope app data for Readiness Assistant residency purposes when stored by the app:

  • derived compliance findings;
  • documentation health findings;
  • redacted sensitive data finding previews;
  • AI inventory metadata;
  • anonymized AI review output;
  • scan summaries and readiness scores;
  • app settings;
  • workflow records, including owner display names entered by administrators.

This data is stored in Atlassian Forge Storage for the app installation.

3. Data Not Stored by the App

Readiness Assistant does not store:

  • raw Confluence page body text;
  • raw Confluence page HTML;
  • original credentials, secrets, tokens, or passwords;
  • raw Forge LLM prompts;
  • raw bounded AI excerpts;
  • original detected sensitive values;
  • customer payment card data;
  • customer billing records;
  • customer API keys.

Raw page content is processed transiently during a scan and then discarded.

4. How Residency Is Determined

For Forge apps that use persistent Forge hosted storage, Atlassian documents that in-scope app data can follow the host Atlassian product's chosen location when the app is eligible.

For Readiness Assistant:

  • the required Atlassian product is Confluence Cloud;
  • app data is stored in Forge hosted storage;
  • no remote app storage is configured;
  • no external app backend is configured.

If the customer's Confluence product is pinned to a supported Atlassian data residency location and the app is eligible for pinned status, Atlassian's platform behavior determines where in-scope app data is hosted and moved.

If the Confluence product is not pinned, Atlassian may show the product or app as Not Set or Global, depending on the customer's Atlassian configuration.

5. Customer Verification

Organization administrators can verify data residency status in Atlassian Administration:

  1. Open Atlassian Administration.
  2. Select the relevant organization.
  3. Go to Data management > Data residency.
  4. Review the Confluence location and any Marketplace app status shown by Atlassian.

If Atlassian displays Readiness Assistant as pinned, the app is following Atlassian's current pinned app data residency behavior. If the app status is not pinned, not shown, or unclear, contact support@steiktech.de and include the Atlassian app details shown in the admin console.

6. Runs on Atlassian Status

Readiness Assistant is designed to run entirely on Atlassian Forge infrastructure and currently uses Atlassian-hosted compute and storage only.

The Runs on Atlassian Marketplace badge must still be verified and granted through Atlassian's Partner Portal process. Until the badge is visible on the Marketplace listing, customers should treat Runs on Atlassian status as pending verification.

7. Important Limitations

  • SteikTech cannot manually pin a customer's app data to a region outside Atlassian's residency controls.
  • Data residency is not selected per page, space, project, user, or framework inside Readiness Assistant.
  • Customer-exported CSV files and Audit Packs leave Forge Storage when downloaded and are then controlled by the customer.
  • Voluntary support emails to support@steiktech.de are outside automated in-app processing.
  • Atlassian controls Forge infrastructure, residency mechanics, migration timing, backups, and platform-level data handling.
  • Optional Forge LLM routing is provided through Atlassian's Forge platform terms and controls.
